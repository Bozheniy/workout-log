# РИТМ — дневник тренировок

Blazor WebAssembly PWA на .NET 10: план из Google Sheets, удобная запись подходов на телефоне и отправка результатов обратно в таблицу.

**Сайт:** https://bozheniy.github.io/workout-log/  
**Подключение Google:** [пошаговая инструкция](docs/GOOGLE_SETUP.md)

## Первый запуск

1. Открой сайт с интернетом. Исходный лист тренера уже указан в настройках.
2. Дождись надписи «Готово к тренировке офлайн».
3. Установи приложение через «Настройки → Установить приложение». На iPhone используй Safari → «Поделиться» → «На экран Домой».
4. Выбери неделю и тренировку. Нажми «Начать тренировку».
5. Если вес и повторы одинаковые, введи их в блоке **«Для всех подходов»** и нажми **«Применить»**: оставшиеся подходы сразу считаются выполненными. Для индивидуальной записи используй поля и галочки подходов. Для правки выполненного подхода сначала сними его галочку. Запас необязателен. Вес `0` подходит для упражнений с собственным весом.
6. Заверши тренировку. Незавершённые упражнения можно явно пропустить. Выполненные подходы при пропуске остатка сохраняются.
7. В настройках нажми «Войти в Google» и выбери аккаунт редактора таблицы. Client ID сайта уже настроен. После входа приложение отправит накопившиеся результаты.

Без входа в Google можно читать доступный план и работать локально. Запись в Google становится доступной после входа в аккаунт, имеющий **права редактора** таблицы. При переносе сайта в другой Google Cloud проект используй инструкцию подключения.

**«Выйти из тренировки»** ставит её на паузу: сохраняются выполненные подходы, частично введённые поля и общий ввод, даже если ещё не нажато «Применить». Позже нажми **«Продолжить тренировку»**. Выход не завершает тренировку и не отправляет её в Google. Если завершение пока невозможно, причина и переходы к незавершённым упражнениям показываются рядом с кнопкой **«Завершить»**.

В **«Настройки → Твой темп»** можно выключить таймер и выбрать длительность отдыха. Выключенный таймер скрыт и не запускается.

## Что уже работает

- Распознавание исходного формата: 10 недель, 4 тренировочных дня, повторяющиеся группы столбцов.
- Загрузка открытой таблицы через CSV; закрытой — через Google Sheets API после входа.
- Отдельная запись веса, повторов и запаса для каждого подхода.
- Общий ввод и подтверждение всех оставшихся подходов; ранее выполненные подходы сохраняют свои значения.
- Одновременно раскрыто одно упражнение. Короткое сравнение «Было / Цель» видно сразу, объяснения и параметры — в «Подробнее».
- Сохранение каждого изменения в IndexedDB, продолжение после перезагрузки.
- Заготовка веса и повторов следующего подхода на основе предыдущего; запас не копируется.
- Прошлая тренировка и цель по каждому подходу: вес, повторы и запас рядом.
- Расчёт двойной прогрессии: сначала повторы в диапазоне плана, затем один настраиваемый шаг веса.
- Учёт фактического запаса и отметки техники, настройки шага и целевого запаса для каждого упражнения.
- Таймер отдыха, история тренировок и объём `вес × фактические повторы`.
- Установка PWA, кэширование приложения и сохранение плана для работы без интернета.
- Автоматическое обновление PWA после сохранения данных и выхода из активной тренировки, без переустановки.
- Долговечная очередь отправки с повторными попытками и увеличением интервалов.
- Раздельные статусы локального сохранения и подтверждения Google.
- Проверка изменений в таблице перед записью и распознавание уже записанных результатов.
- Резервная копия JSON, объединение истории при восстановлении.
- Защита от перезаписи данных устаревшей вкладкой.
- Автоматическая сборка, тесты и GitHub Pages через GitHub Actions.

## Прошлая тренировка и прогрессия

В карточке упражнения есть короткое сравнение **Было → Цель**. Таблица по подходам и объяснение расчёта открываются через **«Подробнее»**. Источник — ближайшая более ранняя неделя того же упражнения в том же дне и листе. Учитываются завершённые локальные тренировки, в том числе ещё не отправленные, и результаты из сохранённой таблицы. Поэтому расчёт работает без интернета после загрузки плана. Текущая и будущие недели, другие листы и незавершённые записи не подменяют прошлую тренировку.

Правила расчёта:

- Если все подходы достигли верхней границы диапазона с нужным запасом, цель — прибавить один шаг веса и начать с нижней границы.
- Иначе вес сохраняется, а цель — по одному дополнительному повторению до верхней границы, при сохранении техники и запаса.
- Если запаса недостаточно, сначала уменьшаются повторения. Если так невозможно попасть в диапазон, вес уменьшается на один шаг.
- При отметке «Были нарушения» прибавки нет: предлагается облегчить вес и восстановить технику. Если отметки нет, рекомендация явно условная.
- Неполная тренировка, неизвестный запас, свободная запись нагрузки или изменившаяся схема плана показываются без автоматической прибавки.

В **Параметрах расчёта** каждого упражнения задаются шаг веса и запас в первом/последнем подходах. Начальные значения — **2,5 кг**, запас **2 → 0**, промежуточные значения интерполируются (например, `2 / 1 / 1 / 0`). Это изменяемые настройки, а не автоматически распознанное назначение тренера. Для гантелей используй ту же единицу веса, в которой ведёшь запись. Упражнения с собственным весом не получают автоматическую прибавку внешнего отягощения.

Для истории из Google понимаются отдельные подходы вида `60 кг × 10`, `60x10` и `60,5 × 10`, разделённые переносом строки, `;` или `/`. Запас нужен отдельно для каждого подхода. Нераспознанное содержимое остаётся видимым. Подсказка не записывает запланированные числа как выполненные.

Настройки прогрессии и оценка техники сохраняются в IndexedDB и JSON-копии. В Google по-прежнему отправляются фактические нагрузка и запас. При переносе только через таблицу оценка техники неизвестна; резервная копия сохраняет её.

## Запись результатов в Google

Приложение сохраняет плановые столбцы «подходы» и «повторы».

В «нагрузка» записываются фактические подходы, каждый с новой строки:

```text
60 кг × 10
60 кг × 9
60 кг × 8
```

В «запас» записывается:

```text
2 / 1 / 0
```

Если запас не введён ни в одном выполненном подходе упражнения, запрос обновляет только «нагрузку»: ячейка «запас» остаётся без изменений, включая существующий текст или формулу. При частичном заполнении сохраняются позиции подходов, например `2 / — / 0`. Пустое значение не превращается в ноль.

Для первой недели это столбцы D–E, для второй — H–I и так далее. Номера строк, название упражнения, параметры плана, ID таблицы и gid сохраняются вместе с тренировкой. Полностью пропущенные упражнения не меняют таблицу. Формулы в ячейках результатов не перезаписываются.

## Архитектура

```text
WorkoutLog.sln
├─ src/
│  ├─ WorkoutLog.Core/
│  │  ├─ Models.cs                Данные плана, тренировок и очереди
│  │  ├─ SheetParser.cs           CSV, URL листа, координаты ячеек
│  │  └─ WorkoutRules.cs          Проверки результатов и конфликтов
│  └─ WorkoutLog.Web/
│     ├─ Pages/
│     │  ├─ Home.razor[.cs]       Тренировка
│     │  ├─ History.razor[.cs]    История и очередь
│     │  └─ Admin.razor[.cs]      Настройки и подключение
│     ├─ Services/
│     │  ├─ AppStore.cs          Состояние и сценарии приложения
│     │  ├─ BrowserStorage.cs    Обёртка над IndexedDB
│     │  └─ GoogleSheetsGateway.cs  Google Sheets API
│     └─ wwwroot/
│        ├─ js/browser.js        Возможности браузера и Google OAuth
│        ├─ service-worker.published.js
│        └─ manifest.webmanifest
├─ tests/WorkoutLog.Tests/        Правила, хранилище, очередь и API
├─ scripts/publish.ps1           Сборка с корректным base path
└─ .github/workflows/pages.yml   Проверка и публикация
```

Разметка отделена от C# через partial-классы `.razor.cs`. Ядро не зависит от Blazor и браузера. JavaScript используется для IndexedDB, service worker, установки, таймера и Google Identity Services. Собственный сервер для этой версии не требуется.

Расширять интеграции следует через отдельные адаптеры рядом с `GoogleSheetsGateway`; новые правила и модели — в `WorkoutLog.Core`. При росте числа пользователей синхронизацию можно перенести в отдельный ASP.NET Core API, оставив клиент и ядро.

Подробности: [архитектура и границы гарантий](docs/ARCHITECTURE.md).

## Разработка

### Суперсеты

Строки вида «Упражнение A + Упражнение B СУПЕРСЕТ» открываются одной карточкой с отдельными полями каждой части. Вес, повторы, необязательный запас, техника и общий ввод на все подходы сохраняются независимо. «Применить» завершает только выбранное упражнение. Таймер запускается после полного круга, а не между частями. В общем прогрессе и объёме учитываются подходы обеих частей.

В Google остаётся одна ячейка нагрузки: результаты разделены названиями упражнений и номерами подходов. Ячейка запаса записывается только при заполненном запасе. История и рекомендации читают результаты каждой части отдельно, включая сохранённую таблицу без сети.

Завершённые старые записи не изменяются. Пустые черновики распознаются автоматически; для старого черновика с общими значениями есть кнопка **«Вводить упражнения отдельно»** — введённое остаётся у первой части, остальные нужно заполнить. Старые общие результаты не используются как подтверждённая нагрузка конкретной части.

### Запуск

Требуется .NET SDK 10. Node.js не нужен для сборки приложения.

```powershell
dotnet restore
dotnet test --configuration Release
dotnet run --project src/WorkoutLog.Web --urls http://localhost:5077
```

Проверки обновления PWA используют Node.js 20+: `node --test tests/WorkoutLog.BrowserTests/pwa.test.mjs`. Они также запускаются в GitHub Actions.

Dev-сборка не кэшируется для офлайн. Для проверки PWA:

```powershell
./scripts/publish.ps1 -BasePath "/"
```

Раздай `publish/wwwroot` любым статическим HTTP-сервером на localhost. Для другого устройства нужен HTTPS. Перед проверкой офлайн дождись полной установки service worker.

Обновления проверяются при запуске, возвращении в приложение, появлении сети и каждые пять минут в открытом приложении. Новая версия полностью кэшируется перед активацией. Автоперезагрузка ждёт выхода из активной тренировки, окончания записи/синхронизации и отсутствия ввода. В настройках есть **«Проверить обновление»**. При переходе с версии без этого механизма достаточно открыть PWA с интернетом, дождаться загрузки, затем закрыть и открыть её; удалять приложение или очищать данные не нужно.

## GitHub Pages

В репозитории уже включён источник **GitHub Actions**. Push в `main` запускает тесты, сборку и публикацию. Pull request выполняет проверку без публикации.

При переносе проекта в другой репозиторий:

1. Settings → Pages → Source → GitHub Actions.
2. Разреши запуск Actions и deployment environment `github-pages`.
3. Обнови origin в Google OAuth, если меняется домен.
4. Измени исходный лист в `wwwroot/appsettings.json` или в настройках сайта.

`publish.ps1` устанавливает `<base href>` **до** `dotnet publish`: контрольная сумма HTML в service worker остаётся корректной. Для обновления страницы `/history` или `/admin` используется копия `index.html` в `404.html`.

## Важные ограничения

- До первого использования без сети приложение и план должны загрузиться полностью.
- Отправка выполняется при открытом приложении, возвращении на его вкладку и восстановлении связи. Фоновая отправка из закрытой PWA не гарантируется.
- Google access token хранится только в памяти. После закрытия приложения или истечения токена может потребоваться снова нажать «Войти в Google». Очередь при этом не теряется.
- Очистка данных браузера, приватный режим, нехватка места или удаление PWA могут удалить локальное хранилище. Есть запрос постоянного хранения и экспорт резервной копии.
- Это личный дневник. `/admin` — экран локальных настроек, а не защищённая панель управления сервером.
- После завершения тренировки запись доступна для просмотра; редактирование выполненных подходов доступно до завершения. Один день одной недели соответствует одной записи; для следующего цикла используй новый лист.
- Перед записью обнаруживаются уже существующие изменения таблицы. Google Sheets API не предоставляет здесь атомарного compare-and-swap, поэтому одновременное ручное редактирование тех же ячеек между проверкой и записью остаётся гонкой. Для строгой многопользовательской блокировки потребуется сервер.
- Синхронизация между устройствами ограничена самой таблицей. Локальная история переносится через JSON; подтверждённые записи из резервной копии повторно не отправляются.
- Перенос строк или изменение структуры плана останавливает запись до ручного разбора конфликта. Данные при этом остаются в истории.
- Тесты API используют имитацию ответов Google. Реальную отправку в пользовательскую таблицу нужно проверить после настройки OAuth; тестовые тренировочные значения в неё не вносились.

Шрифт Manrope поставляется локально по лицензии SIL OFL: [OFL.txt](src/WorkoutLog.Web/wwwroot/fonts/OFL.txt). Приложение не зависит от загрузки внешних шрифтов.
