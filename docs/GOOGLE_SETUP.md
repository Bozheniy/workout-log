# Подключение Google Sheets

Для опубликованного сайта РИТМ OAuth Client ID уже создан в проекте `summer-artwork-385512` и добавлен в `wwwroot/appsettings.json`. На телефоне открой [настройки РИТМ](https://bozheniy.github.io/workout-log/admin) и нажми **Войти в Google**. Идентификатор подставится автоматически; копировать его не нужно.

Ниже — инструкция для переноса приложения или подключения собственного Google Cloud проекта.

## 1. Проект и API

1. Войди в [Google Cloud Console](https://console.cloud.google.com/) своим Google-аккаунтом.
2. Создай отдельный проект, например `РИТМ`.
3. В **APIs & Services → Library** найди **Google Sheets API**.
4. Открой API и нажми **Enable / Включить**.

## 2. Экран доступа

1. Открой **Google Auth Platform**.
2. В **Branding** укажи название `РИТМ`, контактный email и email поддержки.
3. Для обычного личного Gmail-аккаунта выбери **External**.
4. Оставь режим **Testing** для личного использования и в **Audience → Test users** добавь свой email.
5. В **Data Access → Add or remove scopes** добавь:

```text
https://www.googleapis.com/auth/spreadsheets
```

Этот scope даёт приложению доступ к таблицам аккаунта, а не только к одному файлу. Код РИТМ обращается к выбранной таблице и к сохранённым адресам своей очереди. Для более узкого доступа к отдельным файлам следующей версией можно добавить Google Picker и `drive.file`.

Шаги и назначение разделов описаны в [официальной инструкции Google](https://developers.google.com/workspace/guides/configure-oauth-consent).

## 3. Client ID

1. В **Clients → Create client** выбери **Web application**.
2. В **Authorized JavaScript origins** добавь:

```text
https://bozheniy.github.io
```

3. Для локальной разработки можно также добавить:

```text
http://localhost
http://localhost:5077
```

4. Путь `/workout-log/` не добавляй: origin содержит только протокол, домен и при необходимости порт.
5. Для используемого popup token flow redirect URI не требуется.
6. Создай клиент и скопируй **Client ID**, заканчивающийся на `.apps.googleusercontent.com`. **Client Secret приложению не нужен.**

См. [официальную инструкцию создания Client ID](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid).

## 4. Подключение на телефоне

1. Открой [настройки РИТМ](https://bozheniy.github.io/workout-log/admin).
2. Client ID опубликованного сайта уже заполнен. Если подключаешь другой проект, вставь его Client ID и нажми **Сохранить Client ID**.
3. Нажми **Войти в Google**.
4. Выбери аккаунт, который имеет **права редактора** исходной таблицы.
5. Проверь название собственного приложения на экране согласия и предоставь доступ к таблицам.
6. Открой **История**. Завершённые тренировки из очереди начнут отправляться; после подтверждения появится статус **В Google**.

Client ID — публичный идентификатор, его можно включать в клиентское приложение. Значение сайта подставляется автоматически на новых устройствах и при обновлении, если поле ещё пустое. Собственное значение из настроек сохраняется локально и не заменяется. Пароль Google вводится только на странице Google, приложение его не получает. Client Secret в сайт и репозиторий не добавляется.

## Проверка первой реальной записи

Лучше начать с копии таблицы или с реальной завершённой тренировки:

1. Укажи ссылку на нужный лист, включая `gid`, и обнови план.
2. Заполни подходы; оставшиеся упражнения можно пропустить.
3. Заверши тренировку.
4. Дождись статуса «В Google».
5. Открой таблицу: в «нагрузка» должны быть фактические `кг × повторы`, в «запас» — значения по подходам.

Плановые повторы и число подходов останутся прежними. Тестовые данные в исходную таблицу при разработке не отправлялись.

## Если подключение не проходит

| Сообщение / ситуация | Что проверить |
|---|---|
| `origin_mismatch` | В origins нужен `https://bozheniy.github.io`, без пути и завершающего `/` |
| `access_denied` в режиме Testing | Аккаунт добавлен в Test users |
| Окно входа не открылось | Разрешены всплывающие окна; Client ID сохранён; Google доступен по сети |
| Нет прав на запись | Выбран аккаунт редактора; Sheets API включён в том же Google Cloud проекте |
| Срок входа истёк | Нажми «Войти в Google» снова; локальные записи остаются в очереди |
| Изменились план или результаты | Сравни таблицу с карточкой конфликта в истории; автоматическая перезапись остановлена |

Google выдаёт краткоживущий access token. При его истечении нужен новый вход из действия пользователя — это поведение [Google token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model). Поэтому статический сайт не обещает вечную отправку в фоне после закрытия приложения.
